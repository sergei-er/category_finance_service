# Сервис внутренней оценки защиты информации

Учебный проект ВКР для одной финансовой организации. Текущий статус: этап 0, проектирование. Приложения, контейнеров и команд запуска пока нет.

Старт: [требования](docs/REQUIREMENTS.md), [архитектура](docs/ARCHITECTURE.md), [модель](docs/DATA_MODEL.md), [методика](docs/METHODOLOGY.md), [план](docs/IMPLEMENTATION_PLAN.md), [права](docs/PERMISSIONS.md), [пробелы](docs/SOURCE_GAPS.md), [решения](docs/DECISIONS.md), [учебный журнал](docs/LEARNING_LOG.md).

Порядок работы с Git: один учебный этап — одна рабочая ветка и небольшие проверенные коммиты. Перед коммитом просматриваем изменения. После завершения этапа сливаем ветку в `main`. Отправка на удалённый сервер — по отдельной команде пользователя.

Первый репозиторий создаётся на компьютере пользователя (в среде агента `.git` доступен только для чтения):

```bash
git init -b main
git add .gitignore AGENTS.md CODEX_TASK.md README.md docs/*.md
git diff --cached --stat
git diff --cached
git status --short
git commit -m "docs: подготовить проектную документацию этапа 0"
```

Перед коммитом убедиться, что в индексе только `.gitignore` и Markdown-документы. Если Git запросит имя и email автора, задать свои значения через `git config --local user.name` и `git config --local user.email`, затем повторить commit. Email входит в историю коммитов.

`.gitignore` исключает исходные материалы `docs/sources/`, секреты, приватные свидетельства и локальные данные. Он не удаляет ранее отслеживаемые файлы из истории. Для следующего этапа после первого коммита создаётся ветка `git switch -c chore/django-skeleton`; сам этап начинается после отдельной команды.
