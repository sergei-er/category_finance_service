# Проект матрицы полномочий

Удаление сотрудников организации, информационных систем и контуров доступно только администратору. GET открывает подтверждение, запись удаляется только подтверждённым POST с CSRF. Наличие обратных связей (включая M2M систем с обследованиями) блокирует удаление; зависимости повторно проверяются в транзакции. Удаление и запись события `organization.entity_deleted` атомарны. Учётные записи пользователей и профиль организации этим действием не удаляются.

> Актуализация 26.11.2026: только администратор создаёт и запускает обследование; административная роль не выставляет и не утверждает оценки. Специалист заполняет исходные оценки и отдельно согласует каждую корректировку. Проверяющий рассматривает ответы, предлагает корректировки, рассчитывает и утверждает результат. Старые противоположные назначения ниже архивны.

Уточнение 10.11.2026: прикладной журнал действий отключён по явному решению пользователя; версии ответов и решений сохраняются. Прежние требования AuditEvent-журналирования ниже отменены этим решением. Карточка вручную / из учебного шаблона и матрица с вкладками реализованы; объём и ограничения — [INTERFACE_PROPOSAL.md](INTERFACE_PROPOSAL.md).

Актуальная реализация от 10.11.2026 описана в [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md). Ниже сохранены проектные решения и история согласования; сведения «ещё не реализовано» относятся к прежнему состоянию.

Все операции требуют входа; публичной регистрации нет. Объектный доступ проверяется сервером, включая прямой URL и скачивание. Доступ предоставляется в пределах назначенных обследований; назначение доступа выполняет администратор. Для каждого обследования назначаются один сотрудник и один проверяющий — разные пользователи.

| Операция | Администратор | Специалист ИБ | Внутренний проверяющий |
|---|---|---|---|
| Пользователи, роли, профиль, справочники | Да | Нет | Нет |
| Назначение доступа к обследованию | Да | Нет | Нет |
| Создание обследования и выбор области | Нет | Нет | Да |
| Пояснения ответов сотрудника и их свидетельства | Нет | Да, при заполнении/доработке | Не переписывает ответ сотрудника; материалы рассмотрения и фактов — по правилам ниже |
| Чтение назначенного обследования и файлов | По отдельному назначению | Да | Да |
| Решения по ответам, исключениям, компенсациям | Нет | Предложение | Да |
| Расчёт результата и выпуск проекта отчёта | Нет | Нет | Да |
| Утверждение и фиксация результата | Нет | Нет | Да |
| Изменение завершённого обследования | Нет | Нет | Нет |

Это проектные ограничения, не требования о юридической независимости. Административная роль сама по себе не даёт права утверждать результаты. Django superuser технически обходит permissions: использовать только для обслуживания, отдельно документировать и журналировать. Несколько ролей назначаются только отдельным решением администратора. Совмещение ролей не разрешает пользователю утверждать собственные ответы.

Тесты: анонимный запрос; чужое обследование; подмена ID файла; изменение после фиксации; недопустимая роль; CSRF; скачивание закрытого файла через Nginx. Положительный тест дополняет каждый запрет.

## Уточнения от 04.11.2026

Утверждать ответы и итог может только внутренний проверяющий. Изменение ответа специалистом требует нового решения по новой ревизии; старое решение сохраняется в истории. Изменение связанных свидетельств, исключений и компенсаций также требует повторной проверки соответствующих данных.

Закрытое обследование остаётся доступным уполномоченным пользователям для чтения, без изменения оценок и материалов. Повторная оценка проводится в новом обследовании. Закрытие выполняет внутренний проверяющий.

План проверок дополнен: решение по старой ревизии не утверждает новую; один документ допустим для нескольких ответов своего обследования; файл нельзя связать с ответом чужого обследования; закрытое обследование запрещает изменение при сохранении разрешённого чтения. Эти тесты пока не реализованы.

## Переходы и ответственность — 04.11.2026

| Переход / действие | Исполнитель | Условия |
|---|---|---|
| Создание → черновик | Проверяющий | Указаны параметры обследования |
| Черновик → заполнение | Назначенный проверяющий | Администратор назначил одного сотрудника и одного проверяющего, это разные активные пользователи с нужными ролями; параметры обследования заполнены |
| Заполнение → проверка | Специалист ИБ | Вся анкета заполнена, проверка полноты пройдена; отправляется целиком |
| Проверка → доработка | Проверяющий | Указаны замечания и основания возврата |
| Доработка → проверка | Специалист ИБ | Исправления сохранены новыми ревизиями, повторно отправлена вся анкета |
| Проверка → утверждено | Проверяющий | Все необходимые решения приняты по текущим ревизиям, расчёт проверен, снимок зафиксирован |
| Утверждено → закрыто | Проверяющий | Сохраняется утверждённый снимок и доступ для чтения |

Создание, отправка, возврат, утверждение и закрытие согласованы пользователем. Доступ назначает администратор; после назначения одного сотрудника и одного проверяющего черновик переводит в заполнение назначенный проверяющий. Отдельное состояние «утверждение» пока не вводится: действие проверяющего переводит обследование в «утверждено».

Сотрудник редактирует пояснения и свидетельства в разрешённом рабочем состоянии, не числовые оценки. Проверяющий выставляет оценки и мотивировки. Согласованная блокировка: на проверке сотрудник не меняет отправленные данные, сначала требуется возврат на доработку. После утверждения/закрытия содержимое неизменяемо; закрытие — смена статуса без изменения снимка.

План отрицательных проверок: сотрудник не создаёт обследование, не выставляет оценку, не утверждает и не закрывает; отдельный ответ нельзя отправить вместо всей анкеты; неполная анкета не отправляется; отправленные ревизии не подменяются; возврат и повторная отправка сохраняют историю. Тесты ещё не реализованы.

## Повторное рассмотрение анкеты — 04.11.2026

После доработки сотрудник повторно отправляет всю анкету. Проверяющий рассматривает изменённые ответы и затронутые основаниями ответы. Прежнее решение действительно только для той ревизии, по которой принято; новое решение необходимо для новой ревизии. Неизменённые ревизии с прежними действительными решениями повторного утверждения не требуют, если их основания не изменились.

Дополнительные будущие проверки: исправление одного независимого ответа не сбрасывает решения по остальным 99; замена используемого общего свидетельства в пяти ответах требует повторных решений для всех пяти; загрузка новой редакции файла не перепривязывает ответы автоматически; история отклонения доступна после повторного принятия. До реализации это критерии, а не выполненные тесты.

08.11.2026, М-04: решение об учёте факта в Z и признании карточки дубликатом принимает только внутренний проверяющий с мотивировкой. Изменение решения сохраняет историю и требует повторной проверки актуальных данных; после фиксации обследования карточки и решения неизменяемы. Право первичного создания/дополнения карточки согласовано ниже; из возможности приложить свидетельство не следует право принять решение по Z.

## Уточнение по письменной части диплома — 08.11.2026

Пользователь предоставил фрагмент раздела 2.2 в беседе; полный файл главы не предоставлен. «Сотрудник» в тексте соответствует роли «Специалист по ИБ» в проектных документах. Администратор назначает доступ к обследованиям, а не утверждает оценки. Проверяющий создаёт обследование и выпускает проект отчёта. Несколько ролей допускаются по отдельному решению администратора; утверждать собственные ответы нельзя. Применять запрет следует с учётом авторства всех использованных версий ответа и подтверждающих материалов, а не только наличия группы Django. Конкретные проверки оформляются до реализации согласования.

Закрытое обследование повторно не открывается для изменения результата. Исправления оформляются новым связанным обследованием; старое сохраняется для чтения. Одного журнала изменений недостаточно, чтобы разрешить редактировать закрытые данные. Двухэтапное совместное утверждение не вводится: проверяющий утверждает и затем закрывает обследование по принятому процессу. Его собственное решение о числовой оценке не считается «собственным ответом сотрудника»; запрет касается проверки им же подготовленных сведений.

Будущие проверки: пользователь с двумя ролями не утверждает подготовленный им ответ; администратор без роли проверяющего не утверждает оценки; назначение/смена доступа журналируются и не меняют авторство старых записей; операция повторного открытия закрытого обследования для правок запрещена. Эти проверки пока не реализованы.

## Назначения и начало заполнения — согласовано 08.11.2026

На обследование назначаются ровно один сотрудник и один проверяющий — разные пользователи. Это ограничение участников одного обследования, а не числа пользователей/администраторов в системе. В черновике допускается ожидание назначения; до перехода в заполнение оба назначения обязательны. Назначение выполняет администратор, переход — назначенный проверяющий. Наличие глобальной роли без назначения не даёт доступа к произвольному обследованию. Создание черновика разрешено роли проверяющего; автор создания не становится назначенным проверяющим автоматически.

Сотрудник не редактирует ответы в черновике. Перевод в заполнение выполняется серверной операцией с проверкой прав и предусловий; назначение участников и переход журналируются. Смена назначения не меняет авторство прежних ответов и не отменяет запрет собственного утверждения; в утверждённом/закрытом обследовании назначения являются частью сохранённой истории. Предусловия смены участников в рабочем обследовании уточняются перед реализацией соответствующей операции.

Будущие проверки: отсутствие одного назначения блокирует начало заполнения; один пользователь в двух назначениях отклоняется; сотрудник и неназначенный проверяющий не выполняют переход; один пользователь может участвовать в разных обследованиях при соответствующих назначениях. Эти проверки пока не реализованы.

## Карточки фактов нарушений — согласовано 08.11.2026

| Действие | Администратор | Назначенный сотрудник | Назначенный проверяющий |
|---|---|---|---|
| Создать карточку, описать обстоятельства и приложить материалы | Нет | Да, при заполнении/доработке | Да, до фиксации, в рабочем состоянии |
| Уточнить сведения, предоставленные сотрудником | Нет | Да, при заполнении/доработке, новой версией | Фиксирует собственные результаты рассмотрения отдельной версией, не переписывая авторство сотрудника |
| Решить об учёте в Z и указать мотивировку | Нет | Нет | Да, по конкретной актуальной версии |
| Признать дубликатом | Нет | Нет | Да, с основанием и ссылкой на основной факт |
| Изменить карточку после утверждения обследования | Нет | Нет | Нет |

Автор создания записи, автор её версии и источник обнаружения нарушения хранятся отдельно. Например, проверяющий может зарегистрировать факт, ранее обнаруженный организацией; это не превращает его в факт, самостоятельно выявленный проверяющей группой. Правила п. 7.10 применяются по подтверждённым обстоятельствам, не по роли создателя карточки.

Изменение рассмотренных сведений создаёт новую версию и требует нового решения; прежнее сохраняется и не подтверждает новую. Сотрудник не редактирует данные во время проверки без возврата на доработку. Администратор управляет доступом, но не принимает предметные решения. После утверждения исправления оформляются новым обследованием, без правки зафиксированных карточек.

Запрет утверждения собственных ответов сотрудника не мешает проверяющему фиксировать самостоятельно обнаруженный факт и принимать по нему мотивированное решение в пределах своей роли; второе совместное утверждение не вводится. Карточка факта и ответ сотрудника — разные виды записи.

Будущие проверки: сотрудник создаёт карточку только своего обследования в разрешённом состоянии, не меняет решение по Z; источник обнаружения не выводится из автора автоматически; новое содержание требует повторного решения; изменение после утверждения запрещено. Это критерии будущих тестов, а не проверенная функциональность.
