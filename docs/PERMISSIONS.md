# Проект матрицы полномочий

Все операции требуют входа; публичной регистрации нет. Объектный доступ проверяется сервером, включая прямой URL и скачивание. Предлагается доступ в пределах назначенных обследований; механизм назначения уточняется перед реализацией.

| Операция | Администратор | Специалист ИБ | Внутренний проверяющий |
|---|---|---|---|
| Пользователи, роли, профиль, справочники | Да | Нет | Нет |
| Создание обследования | Нет | Да | Нет |
| Ответы и загрузка свидетельств | Нет | Да, в рабочем состоянии | Нет |
| Чтение назначенного обследования и файлов | По отдельному назначению | Да | Да |
| Решения по ответам, исключениям, компенсациям | Нет | Предложение | Да |
| Предварительный расчёт и проект отчёта | Нет | Да | Да |
| Утверждение и фиксация результата | Нет | Нет | Да |
| Изменение завершённого обследования | Нет | Нет | Нет |

Это проектные ограничения, не требования о юридической независимости. Административная роль сама по себе не даёт права утверждать результаты. Django superuser технически обходит permissions: использовать только для обслуживания, отдельно документировать и журналировать. Совмещение ролей и запрет собственного утверждения требуют решения до этапа 2.

Тесты: анонимный запрос; чужое обследование; подмена ID файла; изменение после фиксации; недопустимая роль; CSRF; скачивание закрытого файла через Nginx. Положительный тест дополняет каждый запрет.
