# Резервное копирование и восстановление

Комплект включает PostgreSQL и закрытый том свидетельств. Секреты .env и TLS-ключи сохраняйте отдельно с ограниченным доступом. Копия на том же диске не защищает от его отказа; переносите зашифрованный комплект на отдельный носитель. Все копии исключены из Git.

Для базового Compose из корня проекта:

```bash
python3 scripts/backup.py create
python3 scripts/backup.py verify backups/ИМЯ_СОЗДАННОГО_КАТАЛОГА
```

create останавливает app/nginx, снимает pg_dump -Fc и архив evidence, ставит отметку COMPLETE и возвращает контейнеры в работу даже при ошибке. Каталог/файлы создаются с umask 077. При отсутствии COMPLETE комплект не готов. Скрипт предполагает стандартный Compose и работающий db; не используйте его без адаптации к другому Compose-профилю или с уже остановленным стендом.

verify создаёт уникальную временную базу restore_check_*, восстанавливает её с pg_restore --exit-on-error, проверяет миграции и сверяет SHA-256 каждого свидетельства из архива с восстановленной БД. Архив читается без извлечения путей на диск. В конце удаляется только созданная проверочная база. Основная БД не изменяется. Ошибка завершает команду ненулевым кодом. Проверка выполняется с техническим пользователем postgres, приложение продолжает использовать отдельного ограниченного пользователя finance.

Для аварийного восстановления используйте отдельный Compose-проект с новым .env и чистыми томами; перед командами проверьте имена проекта и базы. Запустите только db и дождитесь инициализации; app ещё не должен писать:

```bash
docker compose -p finance-restore up -d db
docker compose -p finance-restore exec -T db sh -c 'pg_restore --exit-on-error --no-owner --role="$APP_DB_USER" -U "$POSTGRES_USER" -d "$APP_DB_NAME"' < backups/КОПИЯ/database.dump
docker compose -p finance-restore run --rm --no-deps -T app tar -C /app/private-evidence -xf - < backups/КОПИЯ/evidence.tar
```

Только собственные доверенные архивы; не накладывайте копию на заполненную БД. Затем выполните check/showmigrations, проверьте пользователей, снимки и хэши файлов; поднимите app/nginx и проверьте полный сценарий. Полная имитация потери всего хоста и восстановления из внешнего носителя здесь не заявляется. Фактически выполненные проверки перечислены в RELEASE_CHECK.md.
