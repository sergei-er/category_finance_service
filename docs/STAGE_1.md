## Что создано и как проходит запрос

`config.urls` подключает `core.urls`; путь `/` вызывает `core.views.home`. Декоратор require_safe допускает GET/HEAD, остальные методы отклоняет. View передаёт признак режима в `core/templates/core/home.html`; шаблон выводит русский текст и ссылку на CSS. Страница информационная: данные организации не читаются, ORM не вызывается. SimpleTestCase запрещает незаметный доступ к базе и позволяет проверить страницу без PostgreSQL.

В Compose Nginx принимает HTTP только через 127.0.0.1:8080, CSS читает из отдельного статического тома, остальное передаёт Gunicorn внутри сети. Приватный evidence-том доступен только app, к Nginx не подключён. `/media/` и `/evidence/` не выдают файлы; функциональность свидетельств появится на этапе 5. Главная страница явно сообщает, что анкета, расчёт и отчёт ещё отсутствуют.

Настройки разделены: base — общие; development — только HTTP localhost с DEBUG; production — DEBUG=False, secure-cookie, HTTPS redirect, валидация Host/секретов/CSRF origins. Compose всегда выбирает development. Переключение одной переменной в этом Compose не создаёт защищённую инфраструктуру: HTTPS-конфигурация Nginx/сертификаты и проверка доверенного прокси ещё не подготовлены. HTTPS-настройки Django проверяются отдельно, production-развёртывание не заявляется.

## Запуск на компьютере студента

Требуются установленный Docker Engine и плагин Docker Compose. Перед запуском проверить `docker version` и `docker compose version`. Без Docker выполнить этот сценарий нельзя. Секреты создаются локально; существующий .env генератор не перезаписывает.

```bash
python3 scripts/init_dev_env.py
docker compose config --quiet
docker compose up -d --build
docker compose exec app python manage.py migrate --noinput
docker compose exec app python manage.py showmigrations
docker compose exec app python manage.py check
docker compose exec app python manage.py test core --verbosity 2
docker compose exec app ruff check .
docker compose exec app ruff format --check .
```

Если .env уже существует (в том числе создан агентом), первую команду пропустить, не удалять и не перегенерировать пароли. Не показывать вывод полного `docker compose config`: он раскрывает подставленные env; использовать `--quiet`.

Открыть `http://localhost:8080/`. Ожидаются заголовок проекта и жёлтое пояснение HTTP localhost. CSS должен загружаться с `/static/core/site.css`. `/register/`, `/media/test.pdf` и `/evidence/test.pdf` должны возвращать 404. Из браузера отправку POST на `/` можно проверить позже через client/curl: ожидается 405. Остановка без удаления данных: `docker compose down`. Команду `down -v` не использовать для обычной остановки — она удаляет тома.

При сбое: `docker compose ps`, затем `docker compose logs --tail=100 app nginx db`. Перед отправкой логов проверить отсутствие чувствительных данных. Первый запуск требует скачивания образов и пакетов. Изменение Python/template/CSS требует `docker compose up -d --build`, поскольку исходники не подключены bind-mount.

Миграции встроенных auth/contenttypes/sessions поставляются Django, пользовательских моделей пока нет. Не создавались фиктивные пустые миграции. Применение штатных миграций к PostgreSQL требуется для приёмки этапа, хотя главная страница работает без SQL. Начальная настройка PostgreSQL создаёт отдельную app-роль без SUPERUSER/CREATEDB/CREATEROLE; init-app.sh выполняется только на новом томе. Изменение пароля в .env не изменяет автоматически пользователя существующей базы.

## Исправление публикации порта Nginx

По выводу студента app и db healthy, nginx запущен, но PORTS показывает только 80/tcp и 8080/tcp без привязки хоста. В исходной конфигурации все сети Nginx были internal: true, без шлюза для публикации. Исправлено: nginx подключён к обычной ingress (bridge) и внутренней web; app остаётся только в web/database, db — только в database. Порт Nginx по-прежнему 127.0.0.1:8080:8080, порты app/db отсутствуют, evidence не доступен Nginx.

Объяснение поведения: [обсуждение Moby с ответом сопровождающего](https://github.com/moby/moby/discussions/53256). Отличие внутренних сетей от сети frontend также описано в [документации Docker](https://docs.docker.com/engine/network/). Наличие ports в YAML само по себе не доказывает, что порт опубликован запущенным контейнером.

Для применения без пересоздания БД и app:

```bash
sudo docker compose config --quiet
sudo docker compose up -d --no-deps --force-recreate nginx
sudo docker compose ps
curl -I http://127.0.0.1:8080/
```

Ожидается 127.0.0.1:8080->8080/tcp и HTTP 200. Не нужно удалять тома, базу или перезапускать все сервисы. Проверка восстановления привязки и HTTP после этой правки ещё ожидается от студента. Агенту недоступен Docker daemon без интерактивного sudo, поэтому исправление не считается проверенным живым запуском. По предоставленному ps подтверждён запуск контейнеров, но применение миграций и работа страницы через Nginx пока не подтверждены.
