# Полный состав нормативных мер: импорт и сверка

## Переход с SYN на нормативные меры (26.11.2026)

После обновления контейнера администратор открывает старое синтетическое обследование и выбирает **«Создать анкету по ГОСТ вместо SYN»**, затем редакцию полного каталога. Создаётся отдельная анкета: коды, тексты и О/Т/Н берутся из каталога; исходное обследование и его ответы сохраняются без изменений. Для `УЗП.1` импортированный источник задаёт `Т` для всех трёх уровней. Полный состав при всех процессах и жизненном цикле — 667 строк на один уровень.

Форма требует явного подтверждения. Непроверенная редакция разрешена здесь **только для предварительного заполнения**, с заметной маркировкой; расчёт и утверждение остаются запрещены. Действие не подтверждает точность OCR и не повышает `verified`. После использования каталог неизменяем: для завершения нормативной сверки потребуется новая подтверждённая редакция и новая анкета. Обычная форма создания обследования продолжает предлагать только проверенные каталоги. Полный пакет не надо повторно импортировать, если он уже есть в реестре.

## Состояние на 17.11.2026

На локальный стенд загружена отдельная редакция **№2**: «ГОСТ Р 57580.1-2017 — издание 02.2020 — полный состав мер, импорт 1». У каталога и всех 408 записей `verified=False`: автоматическое извлечение не заменяет сверку с изображениями страниц. Полнота подтверждена по описи кодов таблиц, посимвольная достоверность всего текста пока не подтверждена.

## Как подготовить пакет заново

Нужны Python 3.12 и `pdftotext` из Poppler. Django и доступ к БД для подготовки не требуются. Из корня проекта:

```bash
python -m standards.source_catalog
```

Создаются локальные файлы:

- `local-catalogs/gost-57580.1-ed2020/catalog.json` — существующий формат импорта `schema=1`, 294424 байта;
- `local-catalogs/gost-57580.1-ed2020/review.json` — опись кодов и таблиц, страницы, исходные строки, сноски, журнал нормализации кодов и О/Т/Н, хэши текстов и пакета;
- `local-catalogs/gost-57580.1-ed2020/import-check.json` — результат выполненной браузерной проверки, не создаётся конвертером.

Каталог `local-catalogs/` исключён из Git, как и исходные PDF: полный нормативный текст не публикуется автоматически. Конвертер принимает только экземпляр с указанным хэшем. Для другой редакции нужна новая сверка структуры. Повторный запуск воспроизводит пакет; если выходной файл был изменён вручную, конвертер останавливается. Для отдельного пакета используется `--output local-catalogs/другое-имя`.

Формат совместим с существующей цепочкой `core.workspace.catalog_import` → `CatalogImportForm` → `standards.services.import_catalog` → `CatalogVersion`, `RequirementVersion`, `ImplementationRequirement` → `workspace/catalog.html`. Загрузка происходит одной транзакцией. Подготовка файла сама по себе БД не меняет. На этом шаге схема БД, формулы и сценарии обследований не изменялись; пересборка приложения для чтения подготовленного JSON не требуется.

На новом стенде: войти администратором, открыть **Настройки → Импортировать новую редакцию JSON**, выбрать `catalog.json`. На текущем стенде повторять импорт не нужно: редакция №2 уже существует. Одинаковое название нельзя импортировать повторно.

## Что проверяет конвертер

Проверяются ожидаемые диапазоны кодов всех 56 таблиц, принадлежность к таблице, наличие трёх уровней, допустимые О/Т/Н и привязки 17 сносок. Уровни в PDF расположены **3 → 2 → 1**, а в JSON имеют явные ключи. Отдельные OCR-варианты кодов приводятся к кириллице и цифрам только в кодах; исходные обозначения сохраняются в протоколе.

ЗУД.10, РЗИ.9 и ЖЦ.8 занимают по две страницы. Разрешено объединение только этих продолжений при совпадении таблицы и уровней; конфликтующий повтор останавливает подготовку. В тексте сохраняются перечисления. Мягкие переносы снимаются, два разорванных слова с обычным дефисом в ПУИ.25 и ЖЦ.8 соединяются адресно. Сноски добавляются к отмеченным фрагментам соответствующих мер. Сноска `1)` к заголовку таблицы 42 добавляется ко всем её мерам с отдельным обозначением области действия.

Сноски и условия не создают автоматически исключения. В частности, ограничение в сноске к СЗИ.3 относится к отмеченному пункту, а не ко всей мере; сноска `**` таблицы 49 связана с РЗИ.11–14. Четвёртый этап раздела 9 включает эксплуатацию, сопровождение и снятие с эксплуатации.

## Что осталось сверить человеку

Совпадение количества и кодов не гарантирует точность формулировок. В текстовом слое PDF встречаются OCR-ошибки и разрывы внутри слов: в частности, требуют внимания сноски ФД.15 и ЖЦ.8. Не подтверждайте запись с замеченной ошибкой. Сверять нужно изображение страницы PDF, а не только скопированный из него текст.

Для каждой записи проверьте:

1. Полную формулировку, включая отрицания, перечни, условия и продолжения страниц.
2. Способ реализации отдельно для уровней 3, 2 и 1.
3. Таблицу, страницы, процесс/подпроцесс, направление или этап.
4. Все сноски и то, к какому фрагменту они относятся.

Для поиска на текущей длинной странице каталога подходит поиск браузера по коду. Кнопка **«Зафиксировать ручную сверку»** требует описания проверенного источника и результата. Используйте её только после завершённой проверки конкретной записи. Кнопка подтверждения всего каталога станет допустимой после сверки всех записей, но не выполняет повторную нормативную экспертизу.

В текущем интерфейсе нет редактора импортированных формулировок. Обнаруженные расхождения фиксируются локально; исправленный пакет получает новое название и импортируется отдельной редакцией. Предыдущие редакции и связанные обследования сохраняются. Исходный `review.json` полезно оставить неизменным; замечания вести в отдельном локальном файле.

**Открытое ограничение М-01:** отметка «Н» означает необязательность реализации, а не утверждённое исключение из расчёта. Действующее ядро блокирует расчёт для такой позиции без отдельного решения об исключении. Импорт полного состава не разрешает эту методическую неопределённость. Нельзя убирать Н из пакета или массово согласовывать исключения ради получения результата.

## Текущий порядок сверки

Режим обучения отменён новым `sources/REEWORK_TASK.md`; учебных заданий и пауз на согласование этапов нет. Нормативная верификация содержания всё ещё обязательна: полнота описи не доказывает точность OCR. Для каждой проверенной записи фиксируются редакция, страница, три способа реализации и найденные исправления. Особого внимания требуют УЗП.2, УЗП.14, ЗУД.10 (оба фрагмента), РЗИ.12 и ЖЦ.19.

С 26.11.2026 анкета создаётся отдельно для каждой группы уровней: 667 позиций полного каталога относятся к **одному** уровню при всех процессах и жизненном цикле. Дополнительный контур того же уровня не увеличивает это число. Наличие «Н» не даёт права автоматически исключить меру или уменьшить знаменатель. Многоконтурный жизненный цикл имеет открытый вопрос М-05, см. `METHODOLOGY.md`.
