# Состояние реализации на 17.11.2026

> Этот файл фиксирует состояние до переработки 26.11.2026 и сохранён как архив. Актуальное состояние находится в [PROJECT_STATUS.md](PROJECT_STATUS.md).

17.11.2026: на локальный стенд импортирована отдельная непроверенная редакция №2 с полным составом кодов таблиц 1–56 предоставленного ГОСТ Р 57580.1-2017: 343 меры раздела 7, 37 раздела 8 и 28 раздела 9, всего 408. Сохранены три уровня, сноски и ссылки на страницы. Полный текст хранится локально вне Git; автоматическая подготовка не выставляет verified. Посимвольная сверка и М-01 остаются открытыми. Инструмент, фактические проверки и порядок работы: [CATALOG_IMPORT.md](CATALOG_IMPORT.md).

По прямому запросу пользователя реализован полный функциональный срез в быстром режиме: объяснения и разбор отложены, учебные задания не резервировались. Этот документ — актуальная сводка; записи этапов 0/1 и дневника сохраняют историю обсуждения.

Работают: вход Django с ограничением пяти неудачных попыток на имя за 15 минут; три группы с разрешениями Django; единственный профиль и контуры; создание обследования проверяющим и назначение отдельного сотрудника администратором; фиксация анкеты; версии ответов; общие свидетельства нескольких ответов одного обследования; отправка всей анкеты; решения по конкретным версиям; доработка; исключения и описание комплекта компенсации; версии фактов, решения об учёте и дубликатах; расчёт с протоколом; неизменяемый через приложение снимок; закрытие; история контура; DOCX/JSON из снимка.

Расчёт работает для одного контура и одного уровня: процессы 1–8, четыре управленческих направления в контексте каждого процесса, жизненный цикл, снижение за учитываемые факты. Формулы (9)–(12) не применяются для объединения обследований. Все вычисления используют Decimal и согласованное поэтапное округление. Пустые узлы/неполные решения блокируют результат; отрицательный R сохраняется. Отметка Н сама не исключает меру; при неразрешённом М-01 такая входная позиция блокирует расчёт.

Каталог импортируется из JSON как непроверенный, независимо от поля verified во входе. Администратор вручную сверяет каждую запись и завершает верификацию. Использованный каталог не изменяется через интерфейс. Снимок анкеты хранит текст, пункт, контекст, уровень и О/Т/Н. Импорт не заменяет сверку полноты с первоисточником.

Демонстрационный каталог **целиком синтетический**: условные коды SYN, никакой перепечатки нормативных мер. Его отметка проверки означает проверку структуры учебного набора, а не нормативную верификацию ГОСТ. Есть черновик и отдельное закрытое обследование с историей исправления; проект отчёта помечен как синтетический.

Файлы: до 10 МиБ; PDF/TXT/DOCX/XLSX; проверка расширения и сигнатуры, ограничения ZIP; случайный путь; SHA-256 как внутренний контроль; проверка прав при скачивании и повторная проверка хэша; принудительное вложение. Это не антивирус и не реализация ГОСТ Р 34.11. Исторически связанный файл нельзя убрать. Приватный том не подключён к Nginx.

Изменения состояния сериализуются блокировкой строки обследования в PostgreSQL. Исторические версии и решения дописываются. Самоутверждение собственного ответа/предоставленного к нему файла запрещено. Администратор не получает доступ к ответам одним фактом административной роли. Проверки полномочий выполняются в сервисах и представлениях. Прямой технический доступ к PostgreSQL не является криптографически защищённым журналом; учётная запись БД приложения не суперпользователь.

Результаты автоматических проверок на PostgreSQL 16 и проверки запуска/HTTPS/копирования фиксируются в [RELEASE_CHECK.md](RELEASE_CHECK.md) после исполнения. Тесты включают независимый пример E_i=0,61 / R=0,67, границы шкал, Н, пустой знаменатель, отрицательный итог, отсутствие/ноль жизненного цикла, повторную проверку, дубликаты фактов, приватные файлы, CSRF, страницы всех ролей, DOCX и воспроизводимость его байтов. Визуальная ручная приёмка в браузере остаётся пользователю.

Ограничения готовности: нет полного вручную сверенного нормативного каталога; М-01 не закрыт; не заявлены актуальная юридическая применимость для конкретного вида финансовой организации, независимое заключение или юридическая подпись; нет подписанного официального комплекта приложений по ГОСТ. Интерфейс и архитектура — учебный внутренний прототип. Базовый Compose — HTTP только localhost. Отдельный локальный TLS-профиль проверен с самоподписанным сертификатом; внешний production требует доверенного сертификата, настройки адресов, хранения секретов, резервирования и эксплуатационной приёмки.

Для разбора после реализации: сначала цепочка POST формы ответа → save_answer → AnswerRevision → шаблон истории; затем блокировки и полномочия; затем чистое расчётное ядро. Новые знания пользователю пока не приписываются.
