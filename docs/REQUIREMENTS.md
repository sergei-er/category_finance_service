Создано 03.11.2026; сверено 09.11.2026. Статус: базовая проектная спецификация с ограничениями STAGE_0_REVIEW.md; реализация отсутствует.

Сервис внутреннего обследования одной финансовой организации. Один редактируемый профиль, несколько контуров, история обследований. Нет tenants, публичной регистрации и заключения независимой проверяющей организации.

Сценарий: администратор заводит пользователей и профиль → проверяющий создаёт обследование, задаёт область, один контур, уровень, период и проверенную версию каталога → администратор назначает одного сотрудника и одного проверяющего (разных пользователей) → назначенный проверяющий переводит черновик в заполнение → специалист заполняет пояснения и свидетельства → отправляет всю заполненную анкету на проверку → проверяющий выставляет оценки и принимает решения → проверяется полнота → выполняется расчёт с протоколом → сохраняется неизменяемый снимок → формируется «Внутренняя оценка / проект отчёта».

Статус ответа, числовая оценка и обоснованное исключение хранятся раздельно. Отсутствующий ответ не равен нулю. Для повторной оценки создаётся новое обследование, связанное с предыдущим; завершённое обследование не редактируется. Исторические результаты не пересчитываются автоматически при изменении каталога.

Приёмка: воспроизводимый Compose-запуск, проверенный каталог и методика, полный синтетический сценарий, отказ при неполноте, проверки доступа к каждой операции и файлу, воспроизводимый отчёт, восстановление резервной копии. Эти функции пока не реализованы.

| ID | Событие | Предусловие | Результат |

| UC-02 | Сотрудник заполняет меру | Мера в области, анкета доступна для заполнения/доработки | Сохранены пояснение, версии ответа и связи свидетельств; оценку сотрудник не задаёт |
| UC-03 | Сотрудник отправляет всю анкету | Заполнены все требуемые пояснения и материалы; нет неразрешённых вопросов полноты | Зафиксирован набор отправленных ревизий, анкета доступна в списке проверки |
| UC-04 | Проверяющий принимает ответ или возвращает на доработку | Анкета на проверке, проверяющий назначен | Решение содержит автора, время, мотивировку и ссылку на ревизию; оценка — только при соответствующем решении |
| UC-05 | Проверяющий согласует исключение | Проверены основание, область и мотивировка | Исключение явно учтено в расчётной совокупности и отчёте |
| UC-06 | Проверяющий оценивает компенсацию | Есть обоснование, описание альтернативы и свидетельства | Решение и оценка связаны с исходной мерой; автоматического исключения нет |
| UC-07 | Рассчитать итоги | Полный набор утверждённых входов, проверенные каталог и методика | Промежуточные показатели, R и протокол; при неполноте результат не определён |
| UC-08 | Выгрузить отчёт | Зафиксирован снимок | Внутренняя оценка / проект отчёта и опись свидетельств |

Отправка анкеты не означает её утверждение или достаточность свидетельств. Точный перечень обязательных полей проверки полноты определяется перед реализацией формы; требование файла для каждой меры автоматически не вводится. Если для отдельной меры недостаточны сведения, вопрос должен быть явно отмечен и разрешён до отправки.

## Граница обследования — согласовано 06.11.2026

Одно обследование относится ровно к одному контуру защиты и одному зафиксированному уровню. Для каждого другого контура создаётся отдельное обследование, даже если уровни одинаковы. В одной организации сохраняются несколько контуров и история обследований каждого. Итог отдельного контура не представляется как общая оценка всей организации; область явно указывается на странице результата и в проекте отчёта. Межконтурное усреднение результатов не выполняется.
