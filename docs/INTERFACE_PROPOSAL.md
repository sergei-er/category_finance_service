# Предложение: карточка обследования и матрица мер

> Архивный референс интерфейса до 26.11.2026. Актуальные требования находятся в [REEWORK_TASK.md](sources/REEWORK_TASK.md); заявления об одном контуре и отключённом журнале не действуют.

Предложение от 09.11.2026; состояние на 10.11.2026: реализован первый срез — карточка вручную / из учебного шаблона и матрица с вкладками. Прикладной журнал отключён, версии ответов и решений сохранены. Полный перечень разделов ниже остаётся планом развития.

## Насколько меняется архитектура

Стек и разбиение на Django-приложения сохраняются. PostgreSQL хранит связанные сущности, Django Forms и сервисы проверяют входы/полномочия, чистый Python-модуль считает показатели. Образ книги Excel применим к навигации, таблицам и сводной панели. Формулы выполняются сервером; пользователь редактирует исходные сведения и решения в пределах своей роли.

Главные изменения — страницы и сценарий запуска. В текущем коде уже есть карточка Assessment и формирование AssessmentItem из каталога по уровню/процессам при begin_assessment. Содержание требования фиксируется в снимке. Для варианта с готовыми настройками можно предзаполнять эту же карточку.

| Предложенный раздел | Основа в коде | Доработка |
|---|---|---|
| Главная | Список dashboard | Сводка заполнения, проверки и результатов |
| Организация | OrganizationProfile | Отдельная страница единственного профиля |
| Обследования | Assessment | Реестр и карточка запуска с двумя вариантами: вручную / из шаблона |
| Контуры | ProtectionContour | Отдельный список; одно обследование относится к одному контуру |
| Требования | CatalogVersion, RequirementVersion, ImplementationRequirement | Читаемый справочник, поиск и группировка; полный нормативный набор ещё не подтверждён |
| Применимость | Обоснование в AnswerRevision, решение ReviewDecision | Отдельное представление применимости и исключений. Если решение должно приниматься до заполнения ответа, потребуется отдельная сущность/операция решения |
| Оценки | AssessmentItem, AnswerRevision, ReviewDecision | Главная матрица с разделами 7/8/9, фильтрами и действиями по роли |
| Свидетельства | Evidence, AnswerEvidence | Реестр файлов, ссылки на ответы и конкретные части документа |

| Расчёт | calculations/engine.py, CalculationRun | Табличная сводка с раскрытием промежуточных значений |
| Отчёт | ResultSnapshot, DOCX/JSON | Печатное представление и PDF требуют отдельной доработки |

Общие разделы организации/контуров/каталога доступны вне обследования. Применимость, оценки, файлы, нарушения, расчёт и отчёт открываются в контексте выбранного обследования, чтобы данные разных периодов не смешивались. Видимость и изменение проверяются на сервере.

## Предлагаемый сценарий

1. Администратор один раз заполняет профиль и создаёт контуры/пользователей.
2. Проверяющий создаёт карточку обследования: контур, уровень, период, редакция каталога, область, жизненный цикл. Вариант «из шаблона» подставляет стартовые настройки; их состав виден до запуска.
3. Администратор назначает отдельного сотрудника и проверяющего. При старте фиксируется набор требований и их содержание.
4. Сотрудник заполняет пояснения и прикладывает свидетельства в строках матрицы. Проверяющий рассматривает версии, задаёт оценки и мотивирует решения.
5. Система рассчитывает промежуточные/итоговые показатели, проверяющий утверждает снимок и закрывает обследование. Новая оценка создаёт новое обследование.

У строки матрицы отдельно показываются: код/ссылка, текст меры, О/Т/Н для уровня, контекст процесса/направления, решение об исключении, пояснение, свидетельства, версия, состояние проверки, числовая оценка и основание. Для разделов 8/9 нельзя подменить содержание простым повтором списка мер раздела 7.

## Что означает шаблон

Для одного учебного варианта достаточно программно предзаполнить форму. Для сохраняемых и повторно используемых вариантов целесообразна небольшая модель AssessmentTemplate: название, версия, версия каталога, уровень, процессы, жизненный цикл/обоснование и настройки области. Обследование фиксирует применённую версию шаблона и собственный набор требований. Ответы, файлы, оценки и прежние утверждения автоматически не наследуются.

Демонстрационный профиль содержит синтетические сведения об организации. Нормативный справочник содержит требования, сверенные с ГОСТ Р 57580.1-2017. Это разные источники: ГОСТ не содержит готовой заполненной карточки конкретной организации. Сейчас в стенде есть только синтетический каталог SYN; переименовывать его в подтверждённый каталог ГОСТ нельзя. Полный импорт/сверка остаются отдельной работой.

«Выбрана мера» как оценка раздела 7, присутствие требования в области и согласованное исключение — разные вещи. Чекбокс в шаблоне не должен незаметно удалять строку из знаменателя. Для исключения сохраняются основание и решение. Н не превращается автоматически в исключение; открытый вопрос М-01 остаётся.

## Образец интерфейса

Просмотрена открытая часть [матрицы SECURITM](https://service.securitm.ru/compliance-matrix/gost-57580): сводка по процессам и направлениям, переходы к жизненному циклу/оценкам и экспортам. Часть действий требует авторизации и не проверялась. Предлагается использовать организацию таблиц и навигации как ориентир; методику и каталог сверять по предоставленным первоисточникам. Наличие формы на стороннем сайте не подтверждает её пригодность для нашего расчёта.

## Реализовано 10.11.2026

- Реестр обследований со сводкой статусов и двумя вариантами создания карточки. Учебный вариант использует только существующий синтетический профиль и подготовленный каталог SYN v1; ничего не создаёт при GET и не заменяет профиль. Ответы и решения не копируются.
- Семь вкладок обследования: карточка, оценки, применимость, свидетельства, нарушения, расчёт, отчёт. Страница методики доступна после входа.
- Матрица разделов 7/8/9: поиск по коду/тексту, фильтры раздела, процесса и статуса. Общие счётчики и отправка всей анкеты не зависят от фильтра. Решение относится только к показанной версии ответа; 0 отличается от отсутствующей оценки.
- Применимость показывает весь зафиксированный состав, основание и состояние решения по исключению. Отметка Н не удаляет строку автоматически.
- Сводка расчёта с переходом к протоколу; DOCX/JSON из утверждённого снимка. Перед отображением зафиксированного результата проверяется его хэш, как на существующем экране снимка.

Миграции БД и изменение формул не потребовались. Организация, контуры и каталог пока остаются в административном разделе; отдельная модель сохраняемых шаблонов, реестр мероприятий и генерация PDF не добавлены. Печатные стили не равны нормативному PDF-отчёту. Следующий срез интерфейса — читаемый справочник требований и работа с подтверждённым каталогом; полная сверка нормативного содержания остаётся отдельной задачей.
